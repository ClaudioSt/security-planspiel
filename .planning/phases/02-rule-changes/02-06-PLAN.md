<objective>
Model the change window in the simulation (RULE-02): a path is a wave-1 plan plus one end state per change window; `evaluate_path` resolves every wave with the selection in force and prices windows exactly (D-01..D-07, D-27), enforces the Kurswechsel swap with the leaf functions of plan 02-05 (D-09, D-12, D-22, D-23, D-28), and books window costs as own spend (D-21). On top, the swap layer (D-24) evaluates every wave-1 plan with every legal Kurswechsel swap: the legal minimum the static reference cannot represent.

Purpose: teams may downgrade, cancel, add and upgrade between waves; the simulation must compute exactly what a facilitator computes for such a game, and Phase 6 needs legal results, not only the static reference.
Output: `simulate_waves`, `Window`, `Path`, `PathError`, `window_cost`, `evaluate_path`, `TierTables` in `planspiel/rules.py`; `enumerate_swap_layer`; swap-layer summary and console; `planspiel tausch`; README change-window rewrite. No golden changes (`evaluate_plan` and the kernel are unchanged; `simulate_selection` delegates to `simulate_waves` with identical output).

Scope note (D-25): the slow trim-back gate over move paths is deferred to Phase 6 and is not part of this plan. Context note: this is the heaviest plan of the phase; tasks are self-contained so each can be executed with the interfaces below without re-exploring the code.
</objective>
