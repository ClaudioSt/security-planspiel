<objective>
Replace the flat −15 Budget-Review penalty by the linear overspend penalty −X KZ per started 10.000 € over budget (RULE-03, D-15), with X a config parameter set provisionally to 9 (D-25, D-17). Over budget is measured once at the end (D-14). The penalty lookup table for print is derived from config.

Purpose: removes the flat-penalty exploit (going far over budget cost the same −15 as going 1 € over) and gives the RULE-04 gate the stored inputs (`kz_pre_review`, `remaining`) it needs.
Output: config key `overspend_penalty`, validator rules, `budget_review_delta` and `penalty_params` in rules, store/kernel/dump columns, new module `planspiel/review_text.py` with `format_eur` and `penalty_rows`, a reviewed over-budget KZ snapshot change, README/CLAUDE.md/PROJECT.md.

Ordering note (deviation from the research order, dependency-driven): this plan runs before RULE-07. RULE-07 removes the `[-100000, -15]` sentinel tier and makes `_tier_lookup` raise below the first minimum; without this plan's negative branch every over-budget plan would then crash. With this plan first, the sentinel becomes unreachable (negative remaining never reaches the tier lookup) and RULE-07 can drop it without any simulation change.

Discretion decision (validator): no `hand_calc.penalty_x` warning for X > 5. D-18 routes "X > ~5" to a STATE.md Phase-6 input logged by the gate plan 02-08; a validator warning would duplicate it, break the "one known warning" invariant pinned by `tests/test_validate.py::test_real_config_has_no_errors_and_one_slope_warning` and the CLI test, and Phase 6 `--strict` would turn a balance question into a hand-calculability error. Those tests therefore stay unchanged on purpose.
</objective>
