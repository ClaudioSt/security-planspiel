<objective>
Prove that LaTeX → PDF can run from code on this machine without ever waiting on MiKTeX, and that it is reproducible. This is the non-interactive smoke gate STATE.md demands as the first Phase 4 plan (D-17, PRINT-01, ROADMAP SC1 mechanism). It delivers the TeX driver (`planspiel/texbuild.py`: preflight, bounded subprocess runner with process-tree kill, aux-stable pass loop, `build_documents`), the shared style `print/planspiel.sty` (reproducibility hardening, Arial, A4, MHP colours, "Seite x von y"), the MiKTeX package list, the `pdf` test marker and a smoke document. A user checkpoint covers the MiKTeX update and the `colortbl`/`tikzfill` install; afterwards the smoke gate must pass with nothing skipped.

Purpose: every later print plan (render stage, stamp, worksheets, Phase 5 cards) builds on a driver that cannot hang and produces identical bytes for identical inputs.
Output: `planspiel/texbuild.py`, `print/planspiel.sty`, `print/miktex-packages.txt`, the `pdf` marker, smoke tests, an updated MiKTeX installation (user action).

Scope boundaries: the Jinja render stage and the `uv run planspiel print` command are plan 04-03 (also PRINT-01); the version stamp in the footer is plan 04-05 (PRINT-11); worksheet layout macros are plan 04-06 (PRINT-03). This plan adds no PyPI dependency (the smoke document is a static .tex file).

Hard rules for the executor (they apply to every command you run in this plan):
- Never run kpsewhich without `--miktex-disable-installer` and never lualatex without `--disable-installer`; always bound the call (`timeout 60` in Bash, `timeout=` in Python). A bare call on a missing file hangs on MiKTeX's invisible installer dialog (research Pitfall 1).
- Never update MiKTeX and never install TeX packages yourself (no `miktex packages install`, no MiKTeX Console automation). That is the user's action at Task 3 (D-17).
- If a TeX process hangs anyway: `taskkill /F /T /IM kpsewhich.exe` or `taskkill /F /T /IM lualatex.exe`, then report it.
- Always `uv run`; never the `python` on PATH.
</objective>

| Boundary | Description |
|----------|-------------|
| Python driver → TeX processes | External binaries that can block on GUI dialogs or loop forever |
| repo files → TeX input | `.tex` and `.sty` content is executed by the TeX engine |
| MiKTeX package repository → local TeX tree | Packages enter the machine only through the user's MiKTeX Console |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-01 | Denial of service | `texbuild` subprocess calls (installer dialog, runaway document) | high | mitigate | `--miktex-disable-installer` / `--disable-installer` on every call, `stdin=DEVNULL`, per-call timeouts, process-tree kill via `taskkill /F /T`; proven by the fail-fast and timeout pdf tests |
| T-04-02 | Elevation of privilege | lualatex shell escape | high | mitigate | Driver never passes `--shell-escape` (restricted mode stays the MiKTeX default); the command list is fixed in `run_lualatex` and asserted by the driver tests |
| T-04-03 | Tampering | job names becoming paths | medium | mitigate | `build_documents` rejects job names outside `^[a-z0-9][a-z0-9_-]*$` before writing; all writes go below the given build dir |
| T-04-04 | Tampering | TeX packages from the MiKTeX repository | medium | mitigate | Installed only by the user at the blocking checkpoint (D-17); the executor never runs a package manager for TeX |
| T-04-05 | Information disclosure | PDF metadata (dates, producer, IDs) | low | mitigate | `\pdfvariable suppressoptionalinfo 1023` in the shared style; metadata test asserts the keys are absent |
</threat_model>
