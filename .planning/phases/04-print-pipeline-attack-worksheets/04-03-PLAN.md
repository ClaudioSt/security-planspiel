<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| config/texts strings → LaTeX source | Untrusted-ish strings become TeX input |
| CLI arguments → file system | Paths for output and build dirs |
| PyPI → project environment | New runtime and dev dependencies |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-10 | Tampering / Elevation of privilege | LaTeX injection via config or text strings (`\input`, `\write18`, `\immediate\write`) | high | mitigate | `tex_escape` as Jinja finalize escapes every special including backslash and rejects non-strings and control characters; `StrictUndefined`; lualatex never gets `--shell-escape` (plan 04-01) |
| T-04-SC | Tampering | `uv add jinja2`, `uv add --dev pypdf` (markupsafe transitive) | high | mitigate | Blocking human legitimacy checkpoint (Task 1, never auto-approved); exact pins; `uv.lock` committed |
| T-04-11 | Denial of service | `planspiel print` waiting on TeX | high | mitigate | Preflight before any build; all TeX calls go through the bounded driver of plan 04-01 |
| T-04-12 | Tampering | output paths | low | accept | Paths come from the maintainer's own CLI options; job names are validated by `build_documents`; no path is derived from config prose |
</threat_model>
