# Phase 07.2 Plan 02: Protection-need table and register Summary

The first Teamheft page now opens with a protection-need table (empty asset rows W1 to W4, gering/mittel/hoch ticks per C, I, A and gesamt, euro legend from the config limits, clinic example row) and carries the register below it, whose risks name a W# and a main goal and read their band from the table. One page, no Overfull line.

## What was built

- **Model (`planspiel/booklet.py`):** `MAX_ASSET_ROWS = 4` (a larger `asset_rows` raises `PrintModelError`); `RegisterPage` gains `page_title`, `need_title`, `need_instruction`, `need_header`, `asset_rows`, `need_example`, `legend_title`, `band_legend`. W-labels come from `asset_prefix` plus `fmt.format_number`; `band_legend` is `"<band word>: <range>"` over `risk.band_ranges`; `need_example` is the first W-label plus the clinic asset, the three band words, and the highest band by the maximum principle (computed in code, a word that is no band word raises). The register example row starts with the first W-label; its decision names the band read from the table ("hoch"). `matrix_title`, `axis_impact`, `band_ranges` are removed.
- **Texts:** new keys `page_title`, `need_title`, `need_instruction`, `asset_prefix`, `need_head_asset`, `head_total`, `legend_title` and the table `sheets.register.need_example`; `head_asset` "Wert (W#)", `head_goal` "Hauptziel"; reworded `instruction`; `review_hint` has a new first sentence (band is the cross in the table, row of the asset W#, column of the main goal) and every later sentence verbatim (D-09: full damage without measures, largest damage when several attacks hit, no hit counts as überschätzt). `example.asset` moved into `need_example`. Was-ist-neu Teamheft line: 84 characters (one-page ceiling), sheet still one page.
- **README:** the learning-goal bullet and the Teamheft bullet of § Spielmaterial describe the protection-need table (Schutzbedarfstabelle, Maximumprinzip).
- **Template:** need table first, then register; loops and placement only.
- **Style:** two new macros, `\tickboxsmall` (3.2 mm square) and `\writelinecompact` (5 mm line). The shared `\tickbox` and `\writeline` are unchanged, so no other page moves.

## Page-1 layout proof

- Final fill line: `PLANSPIEL-FILL page=1 used=721.18031pt text=731.23584pt` (10 pt reserve); booklet is five A4 pages, register title on page 1 only, no `Overfull \hbox` in the log.
- Need table columns: 56 / 19 / 19 / 19 / 19 mm (asset write-in, C, I, A, gesamt), `\tabcolsep` 3 pt, font 8/9.5 pt, tick words stacked with 0.4 mm gaps; each asset row about 36 pt, header 6 mm, example row one line.
- Register table columns: 14 / 28 / 15 / 38 / 9 / 26 / 18 mm (asset, threat plus source, main goal, impact two ticks per line, rank, decision, Rückblick), sum 148 mm, `\tabcolsep` 3 pt, `\parskip` 0 in both tables; rank-cell strut `\rule[-12.5mm]{0pt}{3.5mm}`; rows are content-driven at about 54 pt. Review hint under the table at `\scriptsize` italics, full width.
- Shrinking steps used (in the plan's order, plus one): tick spacing and parskip, write line 6 to 5 mm, strut depth 14.5 to 12.5 mm, instructions and hint set smaller, then a smaller tick box. No writing area, tick or label was dropped.

## Deviations from Plan

**1. [Rule 3 - Blocking] Transitional template lines in Task 1.** The plan assumed the old template would keep rendering and the fast suite stay green after Task 1, but `test_every_printed_fragment_is_in_the_tex` fails once the register model holds fragments the template does not print. The Task 1 commit adds a few plain lines printing the new fields; Task 2 replaces them with the real layout. Commit `519f0e4`.

**2. [Rule 3 - Blocking] Two compact macros in the style file.** The plan said the style file changes only if a macro is needed. With the shared 4 mm tick and 6 mm write line the page overflowed by about 110 pt. `\tickboxsmall` and `\writelinecompact` (names contain the base names so the render tests' substring checks hold) were added, together with the 0 pt `\parskip` and the smaller strut from the plan's shrink order. Commit `6f3b3c7`.

**3. [Minor] Register table width.** The first layout was 0.47 pt too wide (Overfull); the threat column went from 29 to 28 mm.

**4. [Minor] `review_hint` and `\hint` macro.** The hint under the register is typeset inline at `\scriptsize` italic grey instead of via `\hint` (which is `\footnotesize`), to fit the page.

Otherwise the plan was executed as written.
