<objective>
PROT-02: the Teamheft register page opens with a protection-need table (empty asset rows W1–W4, per row C/I/A each gering/mittel/hoch with the config € ranges, a "gesamt" column by the maximum principle, an example row from another industry) instead of the 3×3 matrix; register risks reference an asset W# and a main goal, the Rückblick reads the risk's band from the table; the page stays one page and passes the veil, digit and fill checks.

Purpose: teams cannot estimate likelihood, and every attack happens anyway (CONTEXT domain). Rating the damage per asset and protection goal is the BSI-style protection-need analysis; it keeps the learning goal "risks from the company → CIA → measures" and gives each register risk a band the Rückblick can grade.

Output: protection-need fields in the register model, rebuilt register partial, reworded register texts, README and Was-ist-neu lines, tests.

Decisions honoured: D-01 (no likelihood on a player page), D-02 (empty rows W1–W4 from `asset_rows`), D-03 (ticks gering/mittel/hoch per C, I, A; € ranges once in a legend), D-04 (maximum principle, "gesamt" column; rank column stays the budget order), D-05 (table first, register second, clinic example for both), D-06 (register keeps R1–R5, asset cell references W#), D-07 (C/I/A column is the main goal; the band is read from the table, never rated twice), D-08 (other register columns unchanged), D-09 (only the band is graded; 07.1 D-20, D-25, D-27 rules kept), D-19 (README and Was-ist-neu parts of this plan). Discretion: "gesamt" is a tick set like the C/I/A cells (one reading for the Rückblick and the debriefing); layout per the action below.

Hard rules: `uv run` only; numbers only from config (W-labels, R-labels, rank range, € legend composed in code with `fmt.format_number` / `risk.band_ranges`); prose only in `content/texte.toml`, digit-free, no number words (`sheets.register` is in `PHASE7_PREFIXES`, so "drei", "vier" and the like are forbidden); templates only loop and place; `final_documents/generated/` is not touched (07.2-06 writes it); conventional commits with scope `(07.2-02)`.
</objective>
