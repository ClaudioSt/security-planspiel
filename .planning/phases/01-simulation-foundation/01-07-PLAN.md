## Requirement review (FOUND-06, resolved before planning)

FOUND-06 was checked against CONTEXT D-11 to D-17, D-25 to D-27, D-30 and RESEARCH Q1/Q2. Open points and how this plan resolves them (A-items are planner assumptions; the orchestrator may overrule them):
1. "Measured bounds" (D-30): per tier, summary mode without dump, at most 120 s wall clock and at most 500 MB peak working set; store payload at most 32 B per combination (actual layout 16 B). Basis: research Q2 plus a re-measurement by the planner on 2026-09-30 with a prototype built from the 01-06 exact primitives (memoized): enumeration 38.3-38.8 s per tier, exact-RoS aggregation about 10 s, peak working set 171 MB, 16 B/record. Bounds hold for this machine (Windows 11, 48 GB, uv CPython 3.12); the JSONL dump and legacy `--output` are I/O-bound and excluded from the time bound (research Q2 item 4), the dump still has the memory bound.
2. How over-budget combinations stay bounded: all dependency-valid combinations are evaluated and kept, none are filtered; memory stays flat because each is kept as 16 bytes of integers, never as a dict tree (D-17). Without memoization of pure primitive calls the prototype needed 111 µs per combination (about 87 s per tier, too close to the bound); with memoization 49 µs.
3. Percentiles (D-12): final KZ and RoS, groups in-budget and over-budget only; nearest-rank with p in (0, 5, 25, 50, 75, 95, 100), index `max(0, ceil(p*n/100) - 1)` (research A3); RoS None excluded (D-27).
4. Top-K (D-12): K = 10 default, `--top K` (A5); computed over all valid combinations, each entry carries `over_budget` (A-7.1). Tie-breaks (A4, extended, A-7.2): by KZ = KZ desc, own cost asc, damage asc, code asc; by RoS = RoS desc, KZ desc, own cost asc, code asc; by Final-Index = Final-Index desc, KZ desc, own cost asc, code asc. Best in/over budget use the KZ ordering (D-13).
5. Pareto (D-14, D-25): maximize final KZ, minimize own cost (init + OPEX x waves, no event effects), over all valid combinations; points are distinct (own_cost, kz_final) pairs not dominated by any other combination; each point reports the number of combinations at that pair and the lowest-code example (A-7.3). Prototype counts: 22 / 23 / 25 (low / medium / high), matching research.
6. CLI (D-16, D-26): without `--output` the new summary is written (`--summary PATH`, default `simulation_summary_<tier>.json` in the working directory); `--dump-jsonl PATH` adds the complete dump; `--output` is the unchanged legacy mode. `--budget-min/--budget-max/--budget-utilization` without `--output` and `--summary/--dump-jsonl/--top` with `--output` are rejected with an argparse error (exit 2) instead of being silently ignored (A-7.4). One tier per run, the config's default tier when `--budget-tier` is omitted; all tiers via a shell loop (A-7.5).
7. Dump content: one compact JSON record per valid combination (code, final KZ, KZ after each wave, E-target bits, own and total cost, damage, RoS, Final-Index, over_budget), not the 6 KB per-wave record (A-7.6). The code's digits follow the config measure order listed in the summary's `measures`.
8. Store record (D-17): logical tuple (code, KZ, own cost, RoS, damage, over flag). Stored as integers only (code index, KZ, own cost, total cost, damage in euros, flag); RoS is derived exactly on access through `rules.ros`, so nothing is lost and nothing is rounded (A-7.7).
9. `--budget-max` quirk: plan 01-04 deferred its pin and documentation to this plan; preserved unchanged (it only scales `--budget-utilization`), pinned by a test and documented in README (research Open Question 2, orchestrator resolution in 01-04).
10. FOUND-03 vs a fast kernel: the kernel is a second composition of the shared primitives inside `planspiel/rules.py` (research Pattern 2). To keep every formula single, the parts that `evaluate_plan`/`simulate_selection` compose inline and the kernel would otherwise repeat are extracted first into `budget_ledger`, `e_target_check` and `apply_final_events` (behaviour-preserving, goldens unchanged). Equality over every combination is proven through the pinned digests.
