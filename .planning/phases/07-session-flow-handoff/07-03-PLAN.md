<objective>
FLOW-04 (part 1 of 2): the data side of the "Was ist neu" sheet. Freeze what the MHP facilitators printed and played as `content/mhp_baseline.json`, prove where it came from, and compute the old -> new value changes against the current config. Part 2 (plan 07-06) turns these changes plus the rule, flow and material rows into the one-page PDF.

Purpose: D-12 requires every number on the sheet to come from config, so the sheet stays right after a future rebalance; that needs a machine-readable old state and a diff that only shows what changed (D-14).
Output: the baseline file, `planspiel/was_neu.py` with loader and diff (no texts, no rendering yet), isolation and provenance tests, stamp inputs.

Why the split (user rule: one requirement per plan; split only when necessary): FLOW-04 as one plan would hold a curated baseline of all ten measures, three attacks and seven events, a diff engine, isolation and provenance proofs, roughly forty prose keys, a template, CLI and render wiring and a one-page PDF proof. That exceeds one executor's context budget (about 70 percent). The cut is clean: this plan owns no prose and no rendering, so it runs in wave 1 next to LEG-01 and FLOW-02 without touching their files.

Decisions honoured: D-14 (frozen baseline file, only the "Was ist neu" builder reads it, table shows only changed values, candidate commit confirmed), D-26 (printed value wins; the one disagreement is the Budget Review boundary, recorded in the file's `source` block and in RESEARCH §Q1). The MHP workshop date question (RESEARCH A6) does not touch this plan: the baseline names commits, never a date.
</objective>
