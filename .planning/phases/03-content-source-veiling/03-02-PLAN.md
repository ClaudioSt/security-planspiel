<objective>
Give every attack a veiled pre-attack text and a separate revealed at-wave text, and make the separation structural (VEIL-01, ROADMAP SC3). The veiled text is the title word "Angriff" (D-26); the number comes from the wave position in code (D-23); the revealed set carried by plan 03-01 stays under `attacks.<id>.revealed`. Audience views (`PreAttackView`, `RevealView`) are the only way later templates read attack texts, and a leak test proves the pre-attack view cannot reach a revealed name or bonus reason. The user reviews the revealed texts and the wording proposals at a blocking checkpoint before the drafted changes are committed (D-13d).

Purpose: players must be able to infer the coming attack but never read its name before the wave; Phases 4/5 templates consume these views so the veil holds by construction.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| content file → pre-wave templates (Phases 4/5) | Pre-wave documents must never receive a revealed name |
| content editor → veiled keys and event texts | Hand edits could add a giveaway term |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
