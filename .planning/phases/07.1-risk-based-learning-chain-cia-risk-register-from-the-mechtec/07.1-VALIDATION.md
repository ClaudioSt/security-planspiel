# Phase 07.1 — Validation Strategy

> Per-phase validation contract for feedback sampling during execution. Source: `07.1-RESEARCH.md` § Validation Architecture.

---

## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | pytest 9.1.1; markers `slow`, `pdf`, `balance`; `addopts = "-m 'not slow and not pdf' --strict-markers"` |
| **Config file** | `pyproject.toml`; fixtures in `tests/conftest.py` (`printed_set`, `update_golden`) |
| **Quick run command** | `uv run pytest <plan test files> -q` (per plan, see map) |
| **Full suite command** | `uv run pytest -q` and `uv run pytest -m pdf -q` |
| **Estimated runtime** | ~220 s fast suite, ~220 s pdf suite |

---

## Sampling Rate

- **After every task commit:** the plan's quick command (seconds to ~1 min; PDF files add a print-set build of ~1–2 min)
- **After every plan wave:** `uv run pytest -q` plus `uv run planspiel validate && uv run planspiel texts && uv run planspiel clues`
- **Before `/gsd-verify-work` (RISK-10 phase gate):** `uv run pytest -q`, `uv run pytest -m pdf -q`, validate/texts/clues, build, `uv run planspiel print --check` exit 0, byte-identical rebuild
- **Max feedback latency:** 120 s per task commit (pdf checks excepted)
- **No-game-value-change proof:** `git diff simulation_config.json` limited to `risk_matrix` and `session_schedule`; `-m slow`, `-m balance` and `gate --paths` are not required
- **Print freshness during the phase:** from the first input commit of 07.1-01 until 07.1-10 rebuilds the set, `uv run planspiel print --check` is expected to exit 1 (stale). This is the approved exception to the CLAUDE.md "print --check before every commit" rule (Phase 5 decision 05-16: only the phase's last plan writes `final_documents/generated/`; stated in the 07.1-01 hard rules and in each intermediate plan's verification). Exit 2 is still a stop; only 07.1-10 gates on exit 0.
